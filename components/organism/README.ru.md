# Living Software Organism

**Living Software Organism (LSO)** — экспериментальная предварительная публичная реализация архитектуры проектного здоровья, непрерывности, ограниченного восстановления и развития на основе проверенных свидетельств.

## Что это и зачем

Программный проект живёт дольше отдельного сеанса ИИ. Его идентичность, правила и история должны оставаться у проекта, тогда как модели, поставщики и исполнители могут меняться. LSO задаёт небольшие явные контракты для проверки согласованности объявленной идентичности, записи изменений здоровья и описания контролируемого ремонта или восстановления.

Главный принцип: **устойчивый организм — сам программный проект; модели ИИ, провайдеры и исполнители — временные заменяемые органы.** LSO помогает сохранять идентичность проекта между сеансами и инструментами, оценивать состояние по свежим свидетельствам и описывать ограниченное восстановление, не передавая ИИ роль владельца проекта.

## Что входит

Принятая справочная архитектура охватывает гомеостаз, контракты контролируемого ремонта, явную привязку возможностей, Immune Memory, метаболизм ресурсов, историю здоровья и готовность к восстановлению. Контракты ремонта описывают ограниченное намерение, но сами его не выполняют.

Принятая архитектурная база — v0.1–v0.7. Системы органов остаются **экспериментальными и не имеют версии**: Recovery Dependency Contract, Rebirth Capsule, Organ Readiness, Nervous System Tracing, Clean Organism / Autophagy, Supervision Tree и Reproducible Phenotype. Публикация извлечённой реализации не повышает их до v0.8.

Это экспериментальная предварительная реализация, а не стабильный production-релиз. Локальные проверки не доказывают восстановление всего приложения, восстановление на новой машине или побитовую воспроизводимость.

Публикация заблокирована: `LICENSE_DECISION_REQUIRED_BEFORE_PUBLICATION`. Лицензия пока не выбрана; metadata пакета — `UNLICENSED`, пакет private. Remote repository и опубликованный пакет этим extraction не создаются.

## Связь с Project Corpus

Project Corpus — один из возможных долговременных носителей идентичности и непрерывности проекта. Для него предусмотрен небольшой адаптер; другой адаптер может передавать те же необходимые данные. Смысловую власть и каноническое состояние сохраняет сам проект. LSO не заменяет протокол Project Corpus. Для детерминированной работы ядра не требуются база данных, сеть, конкретный провайдер ИИ или дополнительная среда Python Runtime проекта.

## Локальный запуск

Для разработки требуется Node.js версии 26 или новее. Метаданные пакета предназначены для приватной разработки и не означают публикацию.

```sh
npm test
npm run smoke
npm run check
```

Контекст создаётся с явным абсолютным корнем проекта, его идентификатором и адаптером. runtime-файлы сохраняются внутри каталога проекта; по умолчанию используется `.lso-runtime`. Подробности: [архитектура](docs/architecture.md), [безопасность](docs/safety.md), [интеграция с Project Corpus](docs/project-corpus.md), [восстановление](docs/recovery.md) и [экспериментальные системы](docs/experimental.md). Полный список экспортов и примеры приведены в [руководстве API](docs/api.md).

## Чего LSO не делает

LSO не выполняет автономное «самоисцеление» и не запускает работу. Он не исполняет контракты ремонта, команды оболочки, фоновый опрос, сервер, удаление файлов, резервное копирование или восстановление живого состояния, перезапись канонических файлов, смену провайдера, оплату сервисов и внешнюю публикацию. Готовность к восстановлению не даёт права на восстановление. Локальный хеш или Git-коммит не доказывает, что все текущие байты можно получить из надёжного внешнего источника.

**Происхождение идеи.** Образ живого корабля из *LEXX* был только концептуальной искрой и метафорой. LSO — оригинальная архитектура программного обеспечения; это не означает связи с правообладателями, адаптации, зависимости от рантайма или копирования художественной интеллектуальной собственности. Подробнее — [о происхождении](docs/design-origin.md).

Решение о лицензии LSO пока не принято. До публичной публикации необходимо отдельное явное решение; репозиторий не содержит лицензию и не подразумевает её.
