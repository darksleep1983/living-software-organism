# Living Software Organism

[English version](README.md)

**Храните идентичность проекта, его текущее состояние, здоровье и свидетельства восстановления вместе с проектом, а не в одном чате с ИИ.**

LSO - небольшой слой непрерывности и диагностики для проектов, которые переходят между Codex, Claude, Gemini, OpenHands и другими заменяемыми агентами. Он не пытается стать вашим coding-agent. Он хранит состояние у самого проекта и даёт разным агентам одинаковую стартовую точку.

## Старт за несколько минут

Требуются Node.js 26+ и npm.

```sh
npm install living-software-organism@0.1.0-rc.3
npx lso init --dry-run
npx lso init --yes
npx lso doctor
```

Этого достаточно для начала. Перед применением проверьте dry-run.

`init` не меняет исходный код, не устанавливает зависимости проекта, не запускает build, не создаёт Git-коммит и ничего не публикует.

## Простая модель

Для обычной работы достаточно четырёх понятий:

| Понятие | Что означает |
|---|---|
| **Идентичность проекта** | Что это за проект, его правила и границы |
| **Текущее состояние** | Что верно сейчас и какая работа активна |
| **Здоровье** | Согласовано ли объявленное состояние проекта |
| **Свидетельства восстановления** | Что реально проверено о восстановлении объявленной основы проекта |

Сам проект хранит свою непрерывность. Модели и исполнители заменяемы.

### Минимальная повседневная непрерывность

Читаемое человеком ядро:

```text
AGENTS.md
.project-corpus/state/PROJECT.md
.project-corpus/state/STATUS.md
```

Небольшой machine-readable policy-файл и `lso.config.json` безопасно связывают инструменты с проектом.

**Не нужно** создавать Task и Report для каждой мелкой правки. Durable Tasks/Reports нужны, когда этого требует локальный протокол проекта или работа существенная, делегированная, рискованная, продолжается между сессиями либо требует долговечных доказательств.

## Основные команды

```sh
npx lso doctor
npx lso status
npx lso context --json
npx lso recover plan
npx lso recover rehearse
```

- `doctor` проверяет идентичность, непрерывность, здоровье и готовность восстановления без изменения canonical-файлов.
- `status` показывает короткий текущий снимок.
- `context --json` даёт агенту ограниченные указатели и evidence, но не заменяет чтение authority проекта.
- `recover plan` показывает, что известно, чего не хватает и что остаётся недоказанным.
- `recover rehearse` проверяет объявленную основу изолированно и никогда не разрешает live restore.

## Продвинутая архитектурная терминология

Биологические названия - это словарь архитектуры, а не обязательные знания для начала работы:

| Термин архитектуры | Обычный инженерный смысл |
|---|---|
| Homeostasis | Вычисляемое здоровье проекта |
| Immune Memory | Проверенные переиспользуемые уроки |
| Metabolism | Бюджеты ресурсов и наблюдения |
| Health History | История изменений здоровья |
| Recovery Readiness | Evidence по объявленным входам восстановления |
| Autophagy | Только планирование очистки |
| Rebirth Capsule | Ограниченные свидетельства реконструкции |
| Nervous System Tracing | Причинная трассировка исполнения/evidence |
| Phenotype | Сравнение объявленных воспроизводимых свойств |

Стабильные программные namespaces не переименовываются ради совместимости. Экспериментальные Organ Systems остаются без версии.

## Чего LSO намеренно не делает

Нет автономного ремонта, произвольного shell execution, фонового демона, неявной сети, удаления, live restore/overwrite, переключения провайдеров, биллинга или публикации. Evidence не выдаёт полномочий.

Только явная команда `lso origin verify` обращается к объявленному Git origin. Даже успешная проверка исходников не доказывает полное восстановление приложения.

## Связь с Project Corpus

Репозиторий включает Project Corpus как независимо используемый Markdown-first слой непрерывности. Можно использовать только Project Corpus, LSO с другим явным adapter или полный объединённый стек.

Версия пакета `0.1.0-rc.3` описывает жизненный цикл пакета. Принятая архитектура LSO остаётся v0.1-v0.7. Project Corpus остаётся Protocol 2.0 с optional Python Runtime 2.2.0.

## Работа из исходного репозитория

```sh
npm pack ./components/organism --pack-destination .
cd /путь/к/вашему-проекту
npm install --no-save /абсолютный/путь/к/living-software-organism-0.1.0-rc.3.tgz
npx lso init --dry-run
```

Проверки репозитория:

```sh
npm test
npm run check
npm run demo
npm run pack:organism
```
