# CLI, восстановление и работа агентов

CLI LSO — облегчённое представление доказательств Project Corpus V2, принадлежащих проекту, и по умолчанию работает только для чтения. Версия пакета `0.1.0-rc.1` — локальный release candidate; это не архитектурная v0.8. Стабильная архитектура остаётся v0.1–v0.7, экспериментальные системы органов не имеют версии, Project Corpus сохраняет Protocol 2.0 и optional Runtime 2.2.0.

## Подключение

Установите локальный кандидат в существующий проект (см. [начало работы](getting-started.ru.md)). Сначала выполните `lso init --dry-run`, проверьте список файлов, затем `lso init` и подтвердите запрос либо используйте `--yes` только для этого детерминированного плана. Init создаёт минимальную основу Corpus и `lso.config.json`; не устанавливает зависимости, не запускает скрипты и не коммитит. Частичное/несовместимое состояние Corpus и конфликт канонических файлов приводят к отказу без перезаписи. `--json` выдаёт машиночитаемый результат; dry-run ничего не записывает.

## Команды

- `lso --help`, `lso version`: справка и независимые измерения версии.
- `lso doctor [path] [--json]`: диагностика только для чтения, readiness, findings, рекомендации и неизвестные состояния без приукрашивания. Коды выхода: 0 — приемлемо, 1 — деградация/неверная конфигурация, 2 — ошибка использования, 3 — внутренняя ошибка.
- `lso status [path] [--json]`: краткий снимок.
- `lso context [path] --json`: ограниченный handoff доказательств; перед работой прочитайте настоящие обязательные authority-файлы проекта.
- `lso findings [path] [--json]`: findings; ремонт только предлагается.
- `lso recover plan [path] [--json]`: детерминированный план свидетельств; команды не запускаются.
- `lso recover deps [path] [--json]`: описательные зависимости без захвата секретов.
- `lso recover rehearse [path] [--json]`: изолированная репетиция; не восстанавливает canonical state и всегда сохраняет `restore_authorized: false`.
- `lso origin verify [path] --remote <https-or-ssh-url> --commit <40-hex> --file <tracked-path>`: явное сетевое действие. Ограниченный Git fetch по argv во временный каталог; требуется соответствие чистого локального HEAD/index/worktree и точных байтов отслеживаемого файла. Receipt связывает файлы и digest полного дерева. URL с credentials отвергается/секреты не печатаются. Ошибки сети, timeout и неполное покрытие остаются UNPROVEN. `file://` допускается только для fixtures и возвращает `LOCAL_GIT_FIXTURE_VERIFIED`.

Receipt исходного кода не является разрешением на восстановление и не доказывает toolchain, доступность пакетов, секреты, сервисы или данные. Git-проверка не даёт основания выводить `RECONSTRUCTIBLE`; полное восстановление остаётся UNPROVEN/PARTIAL, пока каждый объявленный вход не подтверждён независимо и sound-контрактом.

## Конфигурация

`lso.config.json` описан версионированной JSON Schema в `components/organism/schemas/lso.config.schema.json`. Он связывает ID проекта, adapter Project Corpus и ограниченный runtime path; optional recovery-декларации носят описательный характер. Неизвестные ключи, небезопасные пути и значения, похожие на секреты, отвергаются. Не храните credentials и исполняемые команды. Identity, STATUS и policy Corpus остаются authority и не дублируются здесь.

## Нейтральный к модели workflow агента

1. Получить указатели и ограниченные свидетельства: `lso context --json`.
2. Прочитать в проекте `AGENTS.md`, актуальные PROJECT/STATUS/policy и активный Task; context не заменяет authority.
3. Работать в рамках authority; Tasks/Reports остаются собственностью проекта.
4. Проверить состояние через `lso doctor`, `lso status`, `lso findings`; эти команды не ремонтируют.

Codex: `npx lso context --json`, затем прочитать перечисленную authority. Claude: тот же envelope и обязательные чтения. Gemini/OpenHands и другие агенты: принять JSON, независимо прочитать authority. SDK провайдеров не требуется.

## Безопасность и диагностика

LSO не чинит автоматически, не запускает shell, не опрашивает и не слушает в фоне, не удаляет, не устанавливает зависимости, не перезаписывает canonical-файлы, не делает live restore, не переключает провайдера, не списывает средства и не публикует. Единственная явная сетевая проверка — `origin verify`. При ошибках изучите findings и разрешите несогласованность Corpus по authority проекта; не обходите отказ принудительным init. Project Corpus можно использовать отдельно от LSO. См. [безопасность](../components/organism/docs/safety.md), [модель восстановления](../components/organism/docs/recovery.md), [миграцию](getting-started.ru.md#только-project-corpus--миграция).
